Champollion 有两种运行模式。它们共用同一套翻译器——客户内存、解释器、JIT——区别只在脚下垫
什么：你的 Mac，还是一台 Linux 虚拟机。仓库和设计文档里仍然称它们为 **route B** 和
**route A**，所以下面每处提到时都会在括号里保留旧称呼。

## 直接模式：跑在 Mac 上

在 macOS 上执行 `rvrun ./hello`——仓库里叫 route B。客户程序活在单个宿主进程里；系统调用交给
Darwin 后端，由它翻译与 Linux 的差异；其余部分对程序而言就是它期待的 Linux ABI。这是日常开发
的闭环：构建、运行、调试 riscv64 二进制，全程使用 Mac 自己的文件系统，中间没有虚拟机。

调试也在这里：`rvrun -g 1234 prog` 会等待 GDB 远程连接，客户程序停在入口点；断点保存在宿主
一侧（不会改动客户代码），单步执行和 Ctrl-C 都精确可控。

## VM 模式：跑在 Linux 虚拟机里

面向容器和完整发行版时用 VM 模式——仓库里叫 route A。`launcher/` 会构建 `rvcontainer`：拉取
`linux/riscv64` 镜像、解包成 ext4 文件、启动一台 arm64 Linux 虚拟机，并把 `rvrun` 注册为该
虚拟机的 `binfmt_misc` 处理器。在虚拟机里，riscv64 与 arm64 共用系统调用号和结构体布局，因此
客户地址就是宿主地址，运行时没有模拟的调用会直接透传给内核。Alpine 和 Debian 的根文件系统就
这样运行 `apt`、`bash`、`dpkg` 和 CPython，而客户自己的 `execve` 也重新交还给内核处理。

同一个运行时，不同的后端：没有被模拟的系统调用，直接模式把它翻译给 Darwin，VM 模式则把它交到
真正的 Linux 内核手里。

## 该选哪种模式？

在 Mac 上默认用直接模式，它覆盖日常开发。当程序需要完整的用户态环境——包管理器、服务管理器、
容器——或者直接模式尚未模拟的某个系统调用挡在路上时，换 VM 模式。
